# Расчёт стоимости доставки

У вас есть реализация и два проходящих теста. В реализации есть ошибки.
Задача — найти недостающие сценарии по требованиям, подтвердить ошибки тестами
и исправить функцию. Начните с [заданий](TASKS.md).

## Требования к окружению

- Node.js 20+ и npm.
- JavaScript, ES Modules, Vitest. TypeScript не используется.
- Сервер, браузер и база данных не нужны.

## Установка и запуск

В терминале перейдите в каталог этого README:

```sh
npm ci
npm test
npm run test:watch
```

`npm test` выполняет один запуск и завершается. `test:watch` повторяет проверки
после сохранения файлов; выход — `q` или `Ctrl+C`. Изначально проходят **ровно два теста**.
Если lock-файл нужно создать заново, используйте `npm install`.

## Интерфейс функции

Файл: `src/calculateDelivery.js`. Именованный экспорт: `calculateDelivery`.
Результат — число, стоимость доставки в рублях.

```js
import { calculateDelivery } from './src/calculateDelivery.js';

calculateDelivery({
  total: 3000,
  isPremium: false,
  deliveryType: 'standard',
  promoCode: null,
});
```

`total` обязателен. Остальные поля необязательны: `isPremium = false`,
`deliveryType = 'standard'`, `promoCode = null`.
Явный `undefined` в необязательном поле также включает значение по умолчанию.

## Бизнес-правила — источник ожидаемых результатов

1. Стандартная доставка (`'standard'`) стоит 350 рублей.
2. Для заказов **от 3000 рублей включительно** стандартная доставка бесплатна.
3. Premium-клиенты (`isPremium: true`) получают бесплатную стандартную доставку.
4. Промокод **`'FREESHIP'`** даёт бесплатную стандартную доставку. Регистр имеет
   значение. Пробелы не удаляются, другие промокоды не дают скидку.
5. Экспресс-доставка (`'express'`) всегда стоит **700 рублей**, независимо от
   суммы, Premium-статуса и промокода, если входные данные допустимы.
6. `total` должен быть конечным неотрицательным числом. Отсутствие суммы,
   неверный тип, `NaN` и бесконечности вызывают `TypeError`.
   Отрицательное конечное число вызывает `RangeError`.
7. Неизвестный тип доставки вызывает `RangeError`, даже при наличии льгот.
8. Сумма **0 рублей допустима**. Допустимы и дробные неотрицательные суммы.

Сначала проверяется сумма, затем тип доставки, затем рассчитывается стоимость.
Если неверны оба поля, приоритет имеет ошибка суммы.
Скидки не складываются: бесплатная доставка стоит 0, отрицательной цены нет.

В рамках задачи `isPremium` передаётся как boolean, `promoCode` — как строка или
`null`. Дополнительную валидацию этих двух полей реализовывать не требуется.

## Файлы и работа с тестами

- `src/calculateDelivery.js` — реализация для исправления.
- `test/start.test.js` — два стартовых примера.
- `TASKS.md` — самостоятельная работа и лист сценариев.

Новые проверки добавляйте в `test/calculateDelivery.test.js`.
Используйте импорты `test`, `expect` и при необходимости `describe` из `'vitest'`;
функция импортируется из `'../src/calculateDelivery.js'`.

```sh
npm test -- test/calculateDelivery.test.js
npm test -- -t 'часть названия теста'
```

Сначала сформулируйте ожидаемый результат по правилу, затем запускайте тест.
Падение теста — повод проверить и ожидание, и реализацию. После исправления
запускайте весь набор. Не удаляйте проверки, обнаружившие ошибки.
